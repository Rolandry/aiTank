# 提交信息范例

## 单特性

```
feat: 支持创建资源时指定分类

- 分类枚举下沉到共享契约层作为唯一事实源，各端重新导出，
  避免双份定义漂移
- 创建接口新增可选 category 参数，缺省为 auto 保持旧调用方兼容
- 非法分类值回退为 auto 而非报错，避免客户端传错导致创建失败
- 列表与详情接口携带分类字段供展示

验证
- 新增 category-test（15 项）：四类分类逐一生效、auto 落在合法集合、
  非法值回退、未指定时缺省、列表携带字段
- 既有回归 A（29 项）、B（100/100）通过
```

要点：每条要点都说明了「为什么」。「非法值回退而非报错」附带了理由。

## 多特性合并（契约层交织，无法拆分）

```
feat: 状态恢复、双模式与分类选择

状态恢复
- 引入与连接解耦的会话凭证，客户端持久化后在重连时自动恢复身份
- 中断不再立即判定失败：资源保留至本轮结束，恢复后可继续
- 主动退出与意外中断区别对待，避免被误判

双模式
- modeA：无限重试，按时限结算
- modeB：单次机会，最后存活者胜
- modeB 超时判定为存活优先，其次得分

分类选择
- 分类枚举下沉到契约层
- 创建时可指定或交由系统随机，非法值回退

验证
- 新增 recovery-test(14)、mode-test(11)、category-test(15)
- 既有回归全部通过
```

要点：三个特性同时扩展了创建接口的参数列表，物理上无法拆成能独立编译的提交，故合并并分段说明。

## 含顺手修复

```
feat: 主动退出后可回归本轮

退出规则调整
- 主动退出不再作废凭证，席位保留至本轮结束
- 但仍立即判定失败：退出等价于承受一次失败，付出等价代价，
  避免用退出规避损失
- 回归身份按模式区分：modeA 可继续参与，modeB 仅能旁观

客户端
- 会话增加 left 标记，区分「中断待自动恢复」与「已退出待手动回归」；
  自动恢复逻辑跳过带标记的凭证，避免绕过手动入口
- 首页显示回归入口，本轮已结束则清理凭证并提示

修复
- 恢复接口补充终态校验：席位承诺仅到本轮结束，
  此前结束后仍可回归，会让用户进入无法继续的死局

验证
- 新增 leave-rejoin-test(11)：覆盖退出判定、两模式回归身份、
  回归后状态与操作生效、结束后拒绝回归
- 更新 recovery-test 中已过时的断言（该行为为本次刻意变更）
- 既有回归全部通过
```

要点：三处值得学习——

1. 「修复」单列一段，说明了缺陷后果
2. 明确记录了断言更新的原因，避免未来误以为是覆盖率下降
3. 「退出等价于承受一次失败」写清了防滥用的设计意图

## 资源同步

```
chore: 同步更新后的资源文件

- 覆盖 12 个 A 类资源与 5 个 B 类资源，内容均有更新
- 补齐 C 目录下 4 个资源：渲染层一直引用该资源，
  但此前缺失，导致始终以降级方式呈现
- 某资源更名后同步更新引用路径，与资源库命名保持一致
- D 类资源内容无变化，未产生 diff

验证
- 33 个资源经 HTTP 逐一确认可访问（200）
- 引用键与注册项完全对应
- 资源尺寸符合消费方假设
- 构建通过
```

要点：说明了「哪些真变了、哪些没变」，避免 reviewer 困惑于为何部分同名文件无 diff。

## 缺陷修复

```
fix: 修复状态过期后对象卡死

现象
- 缩放效果到期恢复原尺寸时，若处于狭窄区域，
  各方向均被占据导致无法移动

原因
- 尺寸恢复未校验新尺寸的可用空间，直接写入导致重叠

修复
- 新增解卡逻辑：以递增半径搜索最近可用位置
- 搜索上限取「障碍半宽 + 自身半宽 + 余量」，
  确保位于障碍中心时也能脱出
- 兜底回退到初始位置

验证
- 新增 3 项断言覆盖狭窄区域到期、障碍中心脱出、兜底路径
- 既有回归通过
```

要点：现象、原因、修复三段分开。搜索上限的计算依据写清了，避免后人误改。

## 重构

```
refactor: 类型定义下沉到契约层

- 某类型此前在服务端单独定义，契约层仅声明为 string，
  客户端拿不到类型约束
- 现下沉到契约层作为唯一事实源，服务端导入并重新导出
- 新增该类型的成员时不会再漏改一端

验证
- 类型检查、构建通过，行为无变化
```

要点：重构必须说明「解决了什么隐患」，否则看起来是无意义改动。
